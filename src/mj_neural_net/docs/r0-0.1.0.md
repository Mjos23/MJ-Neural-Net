# Provisional lowercase r0: MJ-Neural-r0/0.1.0

Owner: Michael Patrick Bangel. Status: **PROVISIONAL**. Scope: the
MJ-Bangel-Neural-Network-Plugin computational model and its MJ Neural Net clone only.

`r0` labels an assessment of a newly observed cue before any downstream action.
This version defines executable model behavior so it can be tested. It does not
promote the marker into a biological state, a CA2 mechanism, an established MjQ
state, or an alias of uppercase JP/MjQ `R0`. Marker status remains PROVISIONAL
even when the model finds a match. Formal adoption requires a separate versioned
definition and evidence decision; the implementation cannot adopt itself.

## Inputs

The closed `MJ-Bangel-Neural/0.1.0` request contains one cue of nine normalized
features, each a finite decimal string in [-0.9,0.9] or explicit absence; the
first observation time; known entity/relation/context values or absence; and the
preceding command token. It also supplies 1-4 earlier stored patterns, prior
command history, optional later updates and a subsequent disjoint validation
split. Model constants, logical paths and their source references are versioned
files, not producer-supplied overrides. An independent downstream review is a
separate argument, bound to the complete request hash.

## State variables

State consists of the original typed feature variants and known-feature count;
81 shared Hebbian weights with zero diagonal; nine activations per recurrent
layer; the three selected paths, scores and support counts; prior/candidate
validation losses and the update disposition; the top candidate and runner-up
margin; relational checks; and the separately bound supervisor verdict.

No state is persisted automatically between requests. Updated observations must
be supplied explicitly on the next request. The bounded update evaluation is a
model-selection component, not an operating-system repair service.

## Transition rule

1. Validate the closed input. Require every training/validation fact to have been
   available strictly before the query's first observation. Keep the validation
   split later than all training/update facts and prohibit shared identities.
2. Encode absent features as `Feature.Missing`. Initialize a separate latent
   model activation at zero for absent positions; preserve their absence and do
   not count those activations as observations.
3. Train `w_ij = sum_m p_mi*p_mj/(9*M)` with `w_ii = 0` from stored bipolar patterns.
4. Compare the candidate command model with the prior model on held-out Brier
   loss. Promote only for strict improvement with at least three validation
   records. Otherwise retain the prior model. These are new model rules, not a
   substitute for F-007's three qualified windows and 3-of-5 support.
5. Score each declared path using Laplace-smoothed command transitions and
   F-008 gain `0.1*(2/3)^(i-1)`. Choose the highest score; catalog order resolves
   exact ties. The next layer starts from the last selected node of its predecessor.
6. Execute three tied-weight recurrent layers, each with four asynchronous
   sweeps. Nonzero fields target +/-0.9; zero field retains current activation.
   Updates use `dampen(target-current)`, the first-sweep 0.1 step cap and the
   +/-0.9 bound. This finite iteration scheme makes no convergence guarantee.
7. Score stored patterns by final activation polarity agreement. Require at
   least three observed features, score >=0.8 and a winner margin >=0.2. A tie,
   insufficient evidence or weak retrieval produces `ASSOCIATIVE_HOLD`.
8. Test the selected candidate's entity, relation and context against independently
   supplied query metadata. All must be present and exactly equal. Otherwise
   produce `RELATION_HOLD`; equality produces `RELATION_MATCH`.
9. A missing or HOLD downstream review stays `DOWNSTREAM_HOLD`; DENY stays
   `DOWNSTREAM_DENY`. Only a bound PASS and relational match produce an advisory
   ready for further review. Physical actuation and live trading remain false.

## Outputs and uncertainty

Outputs include model status, provisional marker/version, available candidate
or null, explicit observed-feature count, typed original cue, weights, layer
activations, node paths, diagnostic score/margin, update evidence, downstream
review status and hashes binding the input, source, paths, JP and Joanna receipt.

Polarity similarity is not a calibrated probability. A zero latent activation is
not an observed zero. Missing relational data are a structured unavailable value.
Unevaluated update losses are null in the API, with `evaluated=false` retained.
Scores, weights and latent activations are diagnostic model outputs and must not
be consumed as measured physical quantities. Budget, compiler, admission or
runtime failures return errors; partial results are not usable matches.

## Falsification and promotion tests

Mechanistic tests must reject the model if it alters uppercase `R0`, changes
unknown observations into known zero, uses future/synthetic evidence as observed
corroboration, violates bounds, promotes a regressing update, breaks a declared
path, or overrides downstream DENY/HOLD. These are executable contract tests.

The comparative hypothesis is narrower: the relational stage reduces false
matches for a fixed associative candidate generator. Use blinded, disjoint
evaluation labels; paired cues and weights; explicit unknowns, partial/noisy cues,
near-misses and novel entities; and report false matches, missed matches, recall
and coverage in both arms. A useful gain at fixed coverage/recall requires its
own preregistered operating point and representative data; lower false matches
alone cannot establish it when the model simply holds more cases.

The initial 96-case fixture supports fewer false matches in those cases, with a
20-point recall cost. It does not establish a gain at equal recall or validate
hippocampal reproduction. It therefore does not justify promoting `r0` to a
formal biological or MjQ term.
